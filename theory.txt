LESSON 007:

В JSX всегда требуется закрывать HTML-теги:
HTML: <input value='123'>
JSX: <input value='123'/>

В React даже без указания слушателей событий прослушивает некоторый список событий на HTML-элементах, например,
HTML-элемент "div" c атрибутом "id", установленным как "root", прослушивается React-ом на большой список событий.

В React есть встроенная функция "restoreStateOfTarget()", которая сбрасывает состояние HTML-элементов на то, которое
указано в его props. Эта функция не будет срабатывать, если HTML-элементу не указать атрибуты или props.

Чтобы в JSX указать JS-код нужно использовать "{}".

В JSX нужно более конкретно указывать атрибуты. Например, атрибут "maxlength" в нативном HTML может быть указан и как
строка "15", и как число 15. В JSX лучше такой атрибут указывать как число, например, "maxLength={15}".

В JSX при указании атрибута "style" нужно передавать объект:
HTML: style="color: red; border: 1px solid green; background-color: blue"
JSX: style={ {color: 'red', border: '1px solid green', backgroundColor: 'blue'} }

В JSX вместо атрибута "class" используется атрибут "className", так как в нативном HTML при указании класса
HTML-элементу появляется свойство "className" у объекта, связанного с этим HTML-элементом. Поскольку JSX работает с HTML
через JS, то это, скорее, всего объясняет разницу в именах атрибутах между HTML и JSX.

LESSON 008:

Нормализация - это хранение каких-то данных только в одном месте и переиспользование их в других местах только через их
идентификаторы.

Денормализация - это хранение каких-то данных в разных местах путем их дублирования.

LESSON 009:

React перерисовывает компонент только в ответ на изменение каких-то отслеживаемых им данных.

Перерисовка компонента осуществляется путем вызова функции, описывающей этот компонент.

Сеттер в хуке "useState()" планирует перерисовку компонента, во время которой будет произведено обновление каких-то
отслеживаемых данных.

LESSON 011:

Количество вызовов хуков должно соответствовать количеству перерисовок компонента. Поэтому хуки нельзя указывать в
условных конструкциях.

Хук "useState()" хранит локальное состояние в React в объектах типа "Fiber Node". Объекты такого типа создаются вместе с
компонентами.

React может перерисовывать компоненты по своим каким-то причинам, например, в целях оптимизации.

Пустой массив в зависимостях хук "useEffect()" заставить сработать этот хук только один раз.

Хук "useEffect()" регистрирует очереди эффектов внутри объекта типа "Fiber Node" указанный эффект, который выполняется
асинхронно после отрисовки компонента в браузере.

Жизненный цикл монтирования функционального компонента (Lifecycle Mount Mode):
1. Создание объекта типа "Fiber Node" для хранения локального состояния компонента.
2. Render Phase: первая отрисовка компонента путем вызова функции компонента.
3. Заполнение объекта типа "Fiber Node" на основе используемых хуков, props и локального состояния в компоненте.
4. Возвращение JSX в виде объекта типа "React Element".
5. Commit Phase: фиксирование актуальных DOM-элементов на основе возвращенного JSX при помощи низкоуровневых устройств
JS для работы с DOM-деревом.
6. Визуализация актуального DOM-дерева в браузере.
7. Effects Phase: Выполнение эффектов.

Жизненный цикл обновления функционального компонента (Lifecycle Update Mode) при изменении локального состояния
компонента:
1. Render Phase: отрисовка компонента путем вызова функции компонента.
2. Заполнение объекта типа "Fiber Node" на основе используемых хуков, props и локального состояния в компоненте.
3. Возвращение JSX в виде объекта типа "React Element".
4. Commit Phase: фиксирование актуальных DOM-элементов на основе возвращенного JSX при помощи низкоуровневых устройств
JS для работы с DOM-деревом.
5. Cleanup Phase: удаление старых неактуальных эффектов из объекта типа "Fiber Node".
6. Визуализация актуального DOM-дерева в браузере.
7. Effects Phase: Выполнение эффектов.

Жизненный цикл демонтирования функционального компонента (Lifecycle Unmount Mode):
1. Cleanup Phase: удаление эффектов из объекта типа "Fiber Node".
2. Remove from DOM Phase: удаление DOM-элементов из DOM-дерева.
3. Визуализация актуального DOM-дерева в браузере.

LESSON 015:

Если в хуке "useEffect()" вообще не указывать второй параметр, то эффекты, указанные в этом хуке, будут срабатывать при
каждой отрисовке компонента.

Действия, выходящие за рамки изменений в HTML-элементе "div" с аттрибутом "id" равным "root", стоит указывать в хуке
"useEffect()".

Vite при горячей перезагрузке может вызывать срабатывание хука "useEffect()".

Если в зависимостях хука "useEffect()" напрямую указать примитив, то эффекты этого хука сработают только при первой
отрисовке компонента.

Второй параметр хука "useEffect()" нельзя выносить в отдельную переменную и менять количество зависимостей, так как это
количество должно быть постоянным.

Эффекты в некоторых случаях позволительно также вызывать в моменте срабатывания событий в самом JSX.

LESSON 020:

Создание простейшего NPM-проекта: npm init -y
Установка TypeScript как dev dependency: npm install -D typescript
Создание файла "tsconfig.json": npx tsc --init
Компилирование TypeScript-файлов в JavaScript-файлы: npx tsx
Автоматическое компилирования TypeScript-файлов в JavaScript-файлы: npx tsx -w
Выполнение файла через Node.js: node ./dist/index.js

В файле "tsconfig.json" в разделе "compilerOptions" пункт "target" определяет в какую версию JavaScript будет
компилироваться TypeScript.

В файле "tsconfig.json" в разделе "compilerOptions" пункт "module" определяет какая система модулей будет
использоваться. Версия "ESNext" обозначает будущую версию ES-модулей.

В файле "tsconfig.json" в разделе "compilerOptions" пункт "rootDir" определяет директорию, в которой будут находиться
TypeScript-файлы. А пункт "outDir" определяет директорию, в которую будут компилироваться JavaScript-файлы.

В файле "tsconfig.json" в разделе "compilerOptions" пункт "strict" определяет использовать более строгий режим работы
TypeScript.

В Vite-проекте файл "tsconfig.json" ссылается на два файла: "tsconfig.app.json" и "tsconfig.node.json". Файл
"tsconfig.app.json" содержит настройки TypeScript для кода приложения, а файл "tsconfig.node.json" отвечает
исключительно за конфигурацию TypeScript для инструментов сборки, работающих в Node.js.

В Vite-проектах компиляцию и итоговую сборку проекта обычно выполняет не TypeScript, а сам Vite и его плагины. Если
пункт "noEmit" установлен как "true", то Vite будет компилировать файлы в папку "./dist".

Type guard - это код, который добавляет проверку, уточняющую, что какие-то данные в какой-то момент выполнения кода
будут иметь какой-то конкретный тип.
